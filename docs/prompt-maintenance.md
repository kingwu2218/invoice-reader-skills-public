# Maintaining the OpenAI prompt

OpenAI 0.3.17 uses three authoring parts and generates one complete installed
`SKILL.md`. These are maintainer boundaries, not three prompts for users to paste
or optional reference files for the model to load.

| Part | Maintained source | Responsibility |
|---|---|---|
| Goals and principles | [01-goals.md](../skills/openai/prompt/01-goals.md) | Desired workbook and division of work between model and scripts |
| Workflow and custom settings | [02-workflow.md](../skills/openai/prompt/02-workflow.md) | First response, requirements, settings, reading, validation and delivery |
| Prohibited behaviours and error handling | [03-constraints.md](../skills/openai/prompt/03-constraints.md) | Document content as data, preserving values, uncertainty and source-supported corrections |

The [source entry](../skills/openai/SKILL.md) contains discovery metadata and an
ordered include list. `tools/build.py` expands every part before injecting the
package name and invocation metadata. Authoring parts are not copied into dist;
the installed entry contains their full text. Missing, duplicated, unreferenced,
nested or unsafe includes fail the build. Links in parts are relative to the
generated package root, where `references/` lives.

Edit the maintained part, then build and check. Do not edit generated
`dist/codex/invoice-reader-openai/SKILL.md` separately. Other providers retain
their existing family sources; there are no model-version prompt forks.

Part 2 describes how to maintain each user's external `custom.md`; it does not
contain a particular company's settings or answers. Clear user requirements
remain sufficient to proceed. Part 3 is always included and custom settings
cannot override it. Timing-sensitive rules, such as waiting for the policy
response, remain next to their workflow step so the condition stays clear.

Detailed schemas, field rules and PDF reading contracts remain in `core/`.
Commands and environment setup remain in `adapters/`. Link to these resources
instead of duplicating them across the three parts.

## Verification when editing

1. Run `python tools/build.py` and `python tools/check.py`.
2. Run relevant tests, including `tests/test_prompt_parts.py`, verifying that all
   parts are present in the installed entry without authoring fragments.
3. Compare generated bytes. Changed wording or order is a prompt change, even
   when intended only as organization; version it and preserve earlier evidence.
4. Freeze package/reference/grader hashes before fresh behavioral evaluation.
   Keep failures and separate opening grades from extraction scores.

Version 0.3.17 reorganizes the 0.3.16 prose and explicitly states that all parts
apply and custom settings cannot override constraints. The processor, PDF
runtime, field references and tool adapter are unchanged. Fresh evaluation is
separate from 0.3.16; its release check does not automatically qualify 0.3.17.
