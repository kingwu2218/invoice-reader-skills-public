## Evaluation corrections

1. **Opening content, waiting and format are separate.** Presentation-only Markdown/numbering no longer makes exact choices fail. The audit requires one exact question and both exact options, and recognises static combined reads of the installed skill instructions. Workspace changes and other commands still require review. New chats score **3 / 3** for exact question/options and observed pause, but **0 / 3 automatic format passes**: all retain `requires_review` for additional announcement/explanatory text. Their legacy `invalid` results remain recorded.
2. **Raw custom fields follow requested labels.** A model may choose its own internal field keys when creating custom.md. The new references match the exact user-facing labels through that generated configuration; wrong/missing labels still fail. Scoring never rewrites observations or matches by the expected value. Existing raw cases retain their original key-based behaviour. Correct blanks remain outside headline denominators.
3. **Image evidence comes from bound tool outputs.** The auditor pairs actual image calls and returned image content in the exact session trace. A model-written reading ledger alone cannot pass. Missing telemetry is unavailable evidence. Follow-up reports count only new call IDs.

Separately re-auditing the preserved preceding public batch gives exact question/options and observed pause in **11 / 11 started chats**, with **11 / 11 still requiring format review**. Its original **10 invalid / 1 requires_review**, **11 / 12 completed**, field scores and startup failure are unchanged. This is a diagnostic correction, not a new model run or retroactive full pass. The additional audit is retained locally at `eval/runs/openai-0314-first-use-20261011/historical-opening-v2.json`.

The runner records execution-time harness hashes separately from the current reporter hash. UTF-8 reading, report generation and conservative shell-wrapper validation were refined after execution; source/reference/package/model artifacts were not edited. The final audit was checked against the frozen opening observations for unchanged outcomes. This report does not attribute evaluator-only changes to a better prompt.

## Limits and next work

This protocol has two initial payment trials and one energy trial, not three repeats per purpose. It reuses familiar synthetic content across purposes and formats; it is not a handwriting or unseen-layout benchmark. Page/type identities here depend on one document per unique page, so ambiguous multiple-document pages need a different reference identity. Raw checks cover the configured fields and observations, not every raw invoice line or arbitrary evidence quotation. Workbook checks include the configured line items. No company-profile workflow, cancellation, compaction or long batch was tested here.

The remaining practical work is broader unseen documents/handwriting and a small real-user trial, plus resolving the extra opening text if strict format compliance is a release requirement. The package remains experimental. Local regression tests and repository checks are recorded in the development log. No commit or push was made for this work.
