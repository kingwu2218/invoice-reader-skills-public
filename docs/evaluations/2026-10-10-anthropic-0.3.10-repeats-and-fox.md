# Anthropic 0.3.10: Sonnet and Opus repeats, and Fox private regression — 2026-10-10

Follow-up to the [first Claude Code evaluation](2026-10-10-anthropic-0.3.10-claude-code.md). At the owner's request this round ran the recommended `claude-sonnet-5-5` and the owner's earlier `claude-opus-5-5` three times per case. It also tested four authorized private Fox pages. **The package and prompt stayed unchanged** (0.3.10, tree `ae4f97a3…`) in every run. Model identity is what the CLI reported in every event; it is not independently verified. The package remains **experimental**.

Files: [public matrix JSON](2026-10-10-anthropic-0.3.10-repeats.json) / [CSV](2026-10-10-anthropic-0.3.10-repeats.csv), and an [aggregate-only private summary](2026-10-10-anthropic-0.3.10-fox-regression.json). The private summary has no field values, names or paths.

## Owner decisions in this round

- Run Sonnet 5.5 in new chats and repeat the tests. The owner chose the model, and the runner passed it through unchanged.
- **Coal cases are custom-field demonstrations, not accuracy benchmarks.** Their existing answer files stay, so earlier reports and tests remain reproducible. From this round on, coal results are reported only as "the demonstration produced its documented requested fields". No raw references will be added.
- Fox: the owner authorized the Fox 2025 documents for Anthropic in this chat. That supersedes the earlier brief's restriction. The owner chose **only the four already frozen single pages** (private-001/003/004/005), with references confirmed earlier (004 mixed owner-confirmed/provisional). They are known sources reused as regression cases, not fresh holdouts. The references were re-frozen against this package without change.
- Policy replies on private chats: per chat, the owner gave one instruction after seeing the listed waiting chats ("Yes, I have read it."). It was relayed verbatim and recorded as a human reply with its origin. A new set of chats got a new reply; the first reply was not reused. Public chats used the labelled scripted read-later fixture as before.
- Harness fix chosen by the owner: add an evaluation-environment note rather than change the package or auto-approve commands. See below.

## Harness versions and what went wrong first

| Harness | Change | Effect |
|---|---|---|
| v2 | Bash only (from the first report) | Sonnet ×3 public: **3 / 27 completed**. Sonnet combined several scripts in one Bash call. `dontAsk` denied the call, and Sonnet then stopped to ask the user, correctly not working around the denial. 24 chats stopped; all are kept as failed/unscorable. |
| — | A PreToolUse hook approving safe combined commands was written | **Blocked by Claude Code's auto-mode safety classifier as self-modification.** Not used, not worked around; the file was deleted. |
| v3 | First prompt adds a recorded environment note: one script per Bash call, no `cd`/`&&`/`;`/variables/`echo`, and a denial does not block other commands. | Opus 27 / 27. Sonnet 24 / 27. |
| v3.1 | Also allow the supplied interpreter path **without quotes**. | v3's rules only matched `"…/python.exe"`. Sonnet usually writes it unquoted, a literal single command that was wrongly denied. 3 Sonnet chats stopped and others fell back to native PDF reading. This was a harness bug; v3 Sonnet results are kept but not used as the Sonnet result. Sonnet v3.1: 27 / 27. |

The v3 note changes the model's input compared with the first report's runs. It is evaluator-provided environment information, like the interpreter path, and it is not document content. Opus never wrote the unquoted form (its four private denials were combined commands it then split), so Opus v3 and Sonnet v3.1 ran under effectively the same rules.

## Not established

- General accuracy. These are four known single pages, re-used since prompt development, and nine public cases with three repeats each. Three repeats show these values were stable here, not a variance estimate for other documents.
- Fresh-holdout performance. The other 30 Fox PDFs were not used, by the owner's choice.
- The OpenAI comparison on the same pages. Packages, tools and dates differ, so no head-to-head claim is made.
- A real permission-prompt experience. All runs used headless `dontAsk` with recorded rules and an environment note.
- Visual attention or verified model identity, and OCR-assisted reading (Tesseract absent).

## Reproduce

```text
python eval/runner/run.py --package invoice-reader-anthropic --prepare-only --runs 3 --python PYTHON --cases CASES...
python eval/runner/claude_session.py run eval/runs/PREPARED_BATCH --cases CASES... --model YOUR_SELECTED_MODEL_ID --provider "ACCOUNT_ROUTE"
python eval/runner/claude_session.py prepare-private PRIVATE_CASE_DIR... --runs 3 --python PYTHON --out PRIVATE_PREPARED
python eval/runner/claude_session.py run PRIVATE_PREPARED --cases CASE_NAMES... --model ID --provider "ROUTE" --out PRIVATE_EXEC
python eval/runner/claude_session.py say PRIVATE_EXEC/CASE/run-N --text-file OWNER_REPLY.txt --actor human --origin "WHERE THE OWNER GAVE IT" --kind policy_response
python eval/runner/claude_session.py report BATCH
python eval/tools/claude_private_summary.py LABEL=PRIVATE_EXEC --out SUMMARY.json
```

Private cases must already have a holdout/regression lock for the evaluated package hash. The runner verifies it before and after execution. It never sends a scripted reply to a private chat; it waits for the human reply. Private sources, references, predictions and traces stay in ignored `eval/runs/` storage.
