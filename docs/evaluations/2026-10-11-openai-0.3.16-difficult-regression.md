public source documents. References were frozen before calls. Package 0.3.16,

## Scope and evidence

Correct blanks are excluded from accuracy. Status/review cells explicitly named
in the references are included. These are selected-field scores, not proof that
every possible field was verified. Each scenario has one execution; the batch
cannot establish statistical stability, broad handwriting accuracy or readiness
to promote an automatic default. New handwriting/layout holdouts, degraded
scans and broader document diversity remain future work.

Deterministic digit-boundary controls pass the supplied correct transcription
and detect all **4 / 4** injected errors, including custom guessing rejected by
the processor. They make no model calls and are not recognition evidence.

All **3 / 3** extraction executions complete. The **3 / 3** input files and
**7 / 7** configured document records are present, subject to the Fox reference
scope above. Archived route reports show B for Fox, B/B/B for digit boundaries
and C/C for the OCR case. Image tools return 6, 6 and 2 images respectively,
including repeated/enlarged views; these are **14 image returns, not 14 unique
pages**, and do not prove model attention. No Tesseract cross-check is evaluated.

Final verification recomputes every opening and configured extraction score,
checks source/reference/package and all 43 execution-file hashes, and preserves
all **169** historical report files byte-for-byte. The runner's serialized answer
copies are semantically identical to the frozen source JSON. Package/registry
and whitespace checks pass. No new full-suite run is claimed; this turn changes
evaluation evidence/documentation only, with orchestration kept in ignored runs.

The next extraction issue is distinguishing genuine ambiguous leading marks
from readable neighbouring amounts without inferring values from line-item
arithmetic. Any later prompt change needs a separately versioned package and
fresh counterexamples that also retain real leading digits and correct
abstention. Opening wording remains a separate v9 limitation; this batch does
not modify its accepted language or safety checks.
