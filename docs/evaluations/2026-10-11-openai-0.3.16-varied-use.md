# OpenAI 0.3.16 — varied multi-file first use

Two fresh public CLI chats completed their workflows and passed unchanged v9.
The new evaluation exposed an **answer-key identity error**: v1 expected
certificate type `Other`, confusing its worksheet destination with its type.
Both models used `Lab certificate`, as the existing skill instructs. Original
frozen scores are preserved. A separately versioned, retrospective reference
correction accounts for all scoring failures; it is not a prospectively frozen
perfect result.

## Validation and limits

The full suite passed **307 tests** during the original run, including nine new
fixture/reference/workflow tests. After the erratum, the focused suite passed
**11 / 11**, including two new reference-correction controls. A second full-suite
run is not claimed. Controls detect dropped documents, swapped same-page order,
changed totals, invented due dates, unit conversion and the wrong custom purpose.
They also check clean workspaces, reference/code drift, failed-attempt retention
and unavailable scores. Positive workbooks run through the real processor.
Package and whitespace checks pass.

One execution per purpose broadens coverage; it does not establish stability,
real-document accuracy or private handwriting recognition. Easy raster text does
not represent poor scans, rotation, handwriting, OCR-layer conflict or protected
files. Other families received no new model evaluation.

Prompt, package, v9 and original grades were not adjusted after results. V1 is
reproducible but its certificate reference is superseded. Before prospective
confirmation, create a separately versioned plan using v2; do not silently reuse
the v1-bound runner as a corrected benchmark. No commit or push was made.
