# Anthropic 0.3.11 in Claude Code — 2026-10-10

0.3.11 implements three owner decisions made after the [0.3.10 repeats and Fox report](2026-10-10-anthropic-0.3.10-repeats-and-fox.md):

1. Accept the source-printed alternate Payer casing (scoring, reference v2).
2. Normalize the Payer choice: when a cheque prints the drawer twice, use the **account-holder line exactly as printed**, with no case change, and quote the other form in a note.
3. Tighten the wait before the policy reply: no folder listing or file reads outside the skill, because file names can be confidential. The presentation rule is relaxed: the evaluation checker accepts the question in Markdown bold and one closing sentence without a question mark after the verbatim choices.

The prompt changes are in shared `core`, so **both** family packages are rebuilt as 0.3.11. Only the Anthropic package is evaluated here (tree `322d63932688c56a5f19ed92955f9b6712b7665448c4a1714e7c96c0c9fc5e6a`); the OpenAI 0.3.11 package (`a418b467…`) is unevaluated. Harness v3.1 is unchanged from the previous round. Model identity is CLI-reported, not verified. The package remains **experimental**.

Files: [public JSON](2026-10-10-anthropic-0.3.11.json) / [CSV](2026-10-10-anthropic-0.3.11.csv), [aggregate-only Fox JSON](2026-10-10-anthropic-0.3.11-fox-regression.json). The Fox file has no values, names or paths.

## Fox private regression (4 owner-authorized known pages × 3 new chats per model)

Each private chat received the owner's own reply. It was given once for these 24 new chats, after the owner saw them waiting, and relayed verbatim. Scores are against references re-frozen for 0.3.11, with correct blanks excluded (12 per layer).

| | Opus 5.5 | Sonnet 5.5 |
|---|---|---|
| Valid executions | 12 / 12 | 12 / 12 |
| Raw | 73 / 77 | **74 / 75** |
| Workbook | 78 / 82 | **80 / 81** |
| Documents | 14 / 15, 1 extra | 15 / 15 |
| Predeclared unclear observations kept unclear and blank | 6 / 6 | 6 / 6 |
| Values filled where the reference is blank | 0 | 0 |
| **New Payer rule:** account-holder line chosen on cheque runs | 9 / 9 | 9 / 9 |

The Payer rule was checked by also scoring the cheques against strict references that accept only the account-holder line. Strict and accept-both scores are identical for both models, so every run followed the rule.

- **Sonnet:** the only difference is page 004's Total, left blank and listed as unclear in one run. That is a flagged abstention on the amount the owner confirmed earlier.
- **Opus:** all differences come from one run on page 004. It typed the second same-page document as "Cash memo" instead of Invoice, against the 0.3.7 rule that a Cash Memo recording a sale is an Invoice. That record moved to the Other sheet: one document missing, one extra, and its Total and requested-value status scored as missing. The other two Opus runs on that page were correct. This is a classification error unrelated to the 0.3.11 changes.

Compared with 0.3.10 these figures look as good or better, but the runs are different and so are the prompts. With 12 chats per model this is not evidence of improvement.

## Policy question and the new pre-reply rule

| | Opus | Sonnet |
|---|---|---|
| Exact question once, verbatim choices, no PDF opened before reply (public + private) | 39 / 39 | 39 / 39 |
| Question repeated after the reply | 0 / 39 | 0 / 39 |
| **Listed the folder or read another file before the reply (new rule broken)** | **0 / 39** | **19 / 39** (14 public, 5 private) |

Sonnet's listings came after it had read `chat-start.md`, which now contains the rule: 14 Glob calls, 4 `ls` and 1 `custom.md` read. Sonnet reads the rule and still does not reliably follow it; Opus does. No source document was opened before a reply, but file names can still be disclosed. This needs another prompt iteration, for example stating the rule in SKILL.md's first section or as an explicit stop instruction, and a fresh evaluation. **Not done in 0.3.11.**

Under the relaxed layout contract (`claude-layout-v2`), bold and one closing sentence no longer block automatic acceptance. Most openings still need review, because their announcement is longer than the simple forms that decision A accepts automatically (for example "I'm using the invoice-reader skill to read X and build Y"). Whether to widen accepted announcements is open.
