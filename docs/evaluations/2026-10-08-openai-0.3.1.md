### Currency display difference

In `format-payment` repeat 2, the frozen `Requested data / Payment amount` answer is `8,750/`; output is `8,750/ HKD`. Extraction preserved `value="8,750/"` and separately recorded `unit="HKD"`. The source prints `Amount (HKD): 8,750/`. The existing summary formatter joins value and unit, while `Requested values` retains them separately.

This is a display/reference-contract gap, not evidence of misread digits or invented currency. The custom configuration says to preserve printed units; its frozen summary answer omits the currency, and its raw checks do not enumerate `observation.unit`. Repeat 1 omitted that custom unit and passes these checks. Consequently **36 / 36 raw checks must not be described as complete transcription accuracy**. Preserve the original `silent_error` cell classification and 9 / 10 score; do not retrospectively loosen the matcher or erase the discrepancy. Future versioned cases should explicitly require value, unit and context separately and specify the resulting summary display before running a model.

### Observed extraction behaviour

Across all four format executions, the configured checks preserve the leading-zero cheque serial, terminal slash and spaced raw date. Standard workbook amount/date cells normalise correctly; the invoice Total remains blank when only a line amount is printed. The two purposes select their respective payment/project facts without scored extra fields.

Both coal executions preserve the deliberately inconsistent printed total of 105.00 and flag review rather than changing it to the arithmetic result 100.00. The OCR fixture's workbook contains visible-reference values 105.00 and 6,200, instead of the incorrect hidden-text values 100.00 and 8,200. These are output matches; they do not by themselves prove how those values were obtained.

### Workflow and evidence limitations

- **Reminder timing: 0 / 6 first responses met the timing rule.** Every run provided the policy reminder in its second agent message, after reading the skill/configuration. Work continued without a consent gate. This is an entry/harness timing issue to address separately from field accuracy; simply adding more policy text is not demonstrated to solve it.
- Preparation reports select A on the ten native-text page executions and C on the two OCR page executions. Companion ledgers mark all pages checked. However, saved JSONL events contain command execution and agent messages without independently inspectable image-view events. The ledgers alone cannot verify image inspection. Do not claim validated route-reading accuracy or conclude that images were definitely skipped from this logging limitation.
- No route B, new Tesseract OCR, independent dual reading, photographs or handwriting was evaluated in this batch. The OCR fixture already contains an intentionally incorrect text layer. Tesseract was disabled or not found through the run's lookup; this does not establish that it is absent from the computer.
- Only the selected columns were scored. Arbitrary evidence quotations, all optional fields, broad layout generalisation and model superiority remain unmeasured. Two repeats show one display difference; they do not establish stable general accuracy.

## Follow-up priorities

1. Specify and freeze a separate currency/unit regression, including raw unit/context checks and the intended summary display. Keep this run's references and scores unchanged.
2. Make image inspection auditable in the evaluation harness before claiming route C success; distinguish absent telemetry from an actual skipped visual step.
3. Test how an explicitly invoked skill can deliver its reminder before a generic acknowledgement, then add a behavioural timing check.
4. Add independently reviewed handwritten/held-out layouts and route B cases. Repeated public printed fixtures cannot establish handwriting improvements.
