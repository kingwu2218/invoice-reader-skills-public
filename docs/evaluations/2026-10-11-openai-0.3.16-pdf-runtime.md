# OpenAI 0.3.16: PDF renderer compatibility and shared runtime

Date: 2026-10-11. The v9 opening grader and its dependencies remain unchanged. This change targets PDF setup, rendering and adapter commands, not extraction rules or answers.

## Cause and change

The installed system Python has pypdfium2 4.30.0. The previous code used `with PdfDocument(...)`, but this version exposes `close()` without the context-manager exit protocol. The old 0.3.15 probe still reproduces the failure in that same environment. Direct page preparation and recovery used the same incompatible pattern. Image-object bounds also have different accessor names in 4.x and 5.x.

The shared scripts now close documents explicitly, use either supported bounds accessor, and clean up probe page/bitmap/image resources even when rendering fails. Missing dependencies remain unavailable; the probe does not install them or claim reading is complete. The probe now supports `--ocr off` to match preparation without calling Tesseract.

Codex now uses `pdf_runtime.py probe`, `prepare` and `render` with the same entry path and launcher. The dispatcher executes the selected script inside its own interpreter rather than launching a different one. Explicit `uv` setup resolves the shared PDF dependencies; installation-free discovery remains separate and optional. Probe and route reports expose the interpreter and library versions. An explicitly chosen existing interpreter can also use the same dispatcher without installing anything. Setup failure still requires a working native reader or an unprocessed input, not invented success.

The OpenAI package is **0.3.16**, SHA-256 `2f03d23ca01d755c4cf6ed94c752d809ef03df201a94a26d8b8c49dc11bd7743`. The previous 0.3.15 artifact (`dbadd0982cb76f54bcbe2b2141996a6ead202878c0854de591c225fd8b75f7b2`) is archived for the before/after check. The family entry prompt remains unchanged from 0.3.15; adapter instructions and shared runtime change. Shared-code rebuilds also advance Anthropic to 0.3.14 and Google/xAI to 0.1.1; those packages remain experimental and receive no new provider-model evaluation from these OpenAI tests.
