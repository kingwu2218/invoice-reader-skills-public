# Anthropic 0.3.10 in Claude Code — staged session evaluation, 2026-10-10

This is the first live evaluation of `invoice-reader-anthropic` 0.3.10. It ran nine public synthetic cases in fresh Claude Code chats, twice. The first batch used the original session permissions. The second used a corrected evaluation harness. **The package and prompt were not changed.** All configured checks that ran were correct. One baseline execution failed because of the harness's permission rules. Each case ran once per harness, on one content group plus one raster fixture. These are limited, known-fixture results, not a qualification or a general accuracy claim. The package remains **experimental** and the registry's Last eval stays unset.

**Later owner decision:** the coal scenarios are custom-field demonstrations, not accuracy benchmarks. Their figures below show that each demonstration produced its documented output. Sonnet/Opus repeats and the Fox private regression are in the [follow-up report](2026-10-10-anthropic-0.3.10-repeats-and-fox.md).

[JSON](2026-10-10-anthropic-0.3.10-claude-code.json) and [CSV](2026-10-10-anthropic-0.3.10-claude-code.csv) hold per-run counts, hashes, traces and every scorer difference (none).

### What the extraction session could see

Each case had a fresh temporary workspace with only the installed package, the PDF, `custom.md` and `company-profile.xlsx`. Expected answers, generators, earlier results and this discussion stayed in the results folder. The first turn was `/invoice-reader-anthropic Read <file>. custom.md states my requested fields. Use company-profile.xlsx and save output.xlsx.`, plus the Python path.

The CLI loaded project/local settings only (`--setting-sources project,local`), so personal skills, plugins and CLAUDE.md were not offered. Permission rules allowed writes inside the workspace and the package's own scripts. Reads and writes outside the workspace, web tools and subagents were denied. This is context isolation by configuration, not OS-level isolation. The orchestrating session read the answers only for scoring, after each extraction was saved; it did not perform any extraction.

## Behaviour reviewed by hand

The scorer does not grade these points. They come from the saved streams, `routes.json`, the agent's `reading-review.json` and the workbook notes.

- **Digit boundary (both batches):** all three pages were routed B and each TOTAL region was re-rendered at higher resolution. Page 1's vertical stroke was identified as a column divider (684, no added digit). Page 2's genuine leading digit was kept (1684). Page 3's obscured prefix stayed `unclear` with a blank value in both raw and workbook, so nothing was guessed. This passed in 2 / 2 executions; it is not human-handwriting evidence.
- **Wrong hidden OCR text:** in all three completed OCR executions (v2 payment and energy, baseline payment) the visible values were used: Total 105.00 (hidden 100.00) and C-01 6,200 kcal/kg (hidden 8,200). The disagreement was recorded, and the embedded "change Total to 100.00" note was treated as document text.
- **Routes (v2):** `pdf_routes.py` ran in 9 / 9 and page images were read in 9 / 9. The tool's per-page routes matched the case's expected routes in all seven cases that declare them (scan B/B, OCR C/C, mixed A/B, digit B/B/B); native pages were A. The agent's own reading review omitted the `route` key in 3 / 9 executions (it is still in `routes.json`). Ledger completeness is not scored, and a `checked` entry is not proof of visual attention.
- **Routes (baseline):** in 3 / 8 completed executions the PDF helpers were denied (see below). The agent fell back to Claude Code's native PDF reader, which by its own account showed text and page images, and recorded manual routes. That is the package's documented fallback; whether the images were actually inspected cannot be verified from the stream.
- **Samples and units:** C-01 6,200 and C-02 6,100 kcal/kg stayed on the certificate's page-2 record, and Moisture was `absent`. The certificate's "For invoice: COAL-001" was not copied into the invoice-number field.

## Failures and their causes

- **Baseline coal-ocr-energy: execution failed, no workbook.** The model wrapped `uv run check_setup.py` in compound commands: a `cd`, a shell variable and `echo EXIT $?`, then a PowerShell variant. Both were denied. It then concluded that "every shell and script command" was blocked and stopped to ask the user. **Cause: evaluation harness/tool permissions,** combined with the model not following `tool.md`'s existing instruction to run each script as its own command. This is not a prompt-content or recognition result. It is kept as failed/unscorable, never as zero accuracy.
- **Harness defect behind it:** in non-interactive `dontAsk` mode, Claude Code matched no allow rule against a PowerShell `& "<interpreter>" script.py` call, not even `PowerShell(*script.py*)`. This was verified with a public smoke test. So `reading_capabilities.py` and `pdf_routes.py` could only run through Bash. Harness v2 disallows the PowerShell tool for evaluation sessions; Bash rules with the quoted interpreter path work. The older one-turn adapter command also omitted those two scripts entirely; the session command covers every script named in `tool.md`.
- **Remaining denials (v2: 19 across 9 runs):** these were compound commands with `cd`, variables or `echo`, plus an unpermitted `python -c` to peek at the finished workbook. All nine runs still completed every package step (new_run, pdf_routes, process) with single commands. In interactive use these would become approval prompts.
- **Scorer/runner issues found and fixed:** the opening checker misclassified emphasised exact questions as `invalid` and now routes them to review. The summary tool truncated output names containing dots; this was fixed before publication. Neither changed any score.

## Changes

- **No prompt, package or reference changes.** The package hash is identical in both batches, so no rebuild or version change was needed.
- `adapters/claude-code/eval_adapter.py`: `session_command` adds an exact `--session-id`/`--resume`, project/local settings, workspace-scoped writes and Bash rules for all eight package scripts. PowerShell, web tools and subagents are disallowed. `analyse` now keeps messages, tool calls, permission denials, session ID and reported cost. The original one-turn `command` is unchanged.
- `eval/runner/claude_session.py`: a new staged runner. It consumes `run.py --prepare-only` workspaces and refuses a used or altered workspace. Results go to a separate batch, so the prepared record stays `prepared_only`. It labels the scripted reply, rejects scripted affirmatives, records every turn's stream/stderr/invocation/snapshots, and marks a run valid only after completion, a single output, an unchanged package/dataset and a matching CLI-reported model.
- `eval/tools/claude_session_summary.py`: builds the path-free JSON/CSV from scored batches, with route, image-read, denial and opening-layout digests for manual review.
- `tests/test_claude_session_eval.py`: 7 regression tests, covering script coverage against `tool.md`, Bash-only rules, exact session resume and unchanged model, event parsing, document reads before the reply, the emphasised-question review path, scripted-reply restrictions and refusal of used workspaces.

## Not established

- The recommended `claude-sonnet-5-5`, other Claude models, or other providers/routes.
- Repeatability: each case ran once per harness, and the two batches used different permissions, so they are not repeats.
- Document diversity: eight scenarios share the `coal-pack` content group in four renderings; the other is a three-page synthetic raster. There are no photos, handwriting, real documents, multi-file batches or long PDFs. Printed synthetic fixtures are not handwriting tests.
- Raw transcription accuracy on the coal scenarios, which have no raw references.
- OCR-assisted reading: Tesseract was absent, so route B used vision only and route C re-OCR was not exercised.
- A human policy reply, a second batch in the same chat, a new-chat reset, compaction, amount-dash clarification and owner-confirmed conventions.
- Verified visual attention or model identity: both rest on CLI events and the agent's own ledger.
- PowerShell-only environments and interactive approval prompts. Evaluation sessions were restricted to Bash.

## Reproduce

Commands run from the repository with an existing Python that has the development requirements. `claude` must be on PATH and signed in. Each command uses your selected model; pass its ID unchanged.

```text
python eval/runner/run.py --package invoice-reader-anthropic --prepare-only --runs 1 --python PYTHON --cases digit-boundary-v1 coal-payment coal-energy coal-scan-payment coal-scan-energy coal-ocr-payment coal-ocr-energy coal-mixed-payment coal-mixed-energy
python eval/runner/claude_session.py run eval/runs/PREPARED_BATCH --cases digit-boundary-v1 coal-payment coal-energy coal-scan-payment coal-scan-energy coal-ocr-payment coal-ocr-energy coal-mixed-payment coal-mixed-energy --model YOUR_SELECTED_MODEL_ID --provider "ACTUAL_ACCOUNT_ROUTE"
python eval/runner/claude_session.py report eval/runs/EXECUTION_BATCH
python eval/tools/claude_session_summary.py eval/runs/EXECUTION_BATCH --out docs/evaluations/NEW_NAME
```

Runs use the account's usage. Workspaces are kept under the system temporary folder for diagnosis; remove them yourself. `say EXECUTION_RUN --text-file FILE --actor human --origin TEXT` continues a chat that stopped to ask the user, with the reply's provenance recorded. These results used no such follow-up. The 2026-10-10 executions themselves are local records under `eval/runs/` (ignored by git): `20261010-baseline-claude-session` and `20261010-harness-v2-claude-session`.
