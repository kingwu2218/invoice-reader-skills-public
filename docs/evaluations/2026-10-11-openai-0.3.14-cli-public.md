# OpenAI 0.3.14 — CLI public regression and preview preparation

Date: 2026-10-11 (Asia/Hong_Kong). OpenAI remains experimental. Of 12 planned public trials, 11 produced valid scored extractions; one failed before a session started because Codex could not write its session directory. That attempt was retained without replacement. The valid runs score **workbook 219 / 219** configured nonblank checks. The two scenarios with raw expectations score **53 / 53**; coal scenarios do not configure raw accuracy. Correct blanks are excluded: workbook **93**, raw **4**.

All 11 started chats asked the policy question exactly once and none repeated it after the reply. The strict automatic opening audit still records **10 invalid and 1 requires_review**, so this is not a full workflow pass. No recommendation/default was promoted.

## Change and protocol

OpenAI 0.3.14 makes both policy replies explicit in the entry, asks through one response channel, and waits before workspace access. The extraction instructions, including handwritten-number guidance, remain unchanged from 0.3.13. No source-specific answer was added. Shared core remains 0.3.11 and the Anthropic 0.3.13 package hash is unchanged.

The new public_repeats.py runner freezes case/package/source/custom/reference hashes before execution, reserves each trial once, creates a fresh workspace and session per trial, and keeps answers outside the model workspace. The only scripted reply is the labelled public fixture **No, but I will read it before I upload any confidential data**; it is not human consent. No private Fox documents were used. No page images were attached before the reply, and no previous examples or answers were supplied in the chat.

## Results

Classification tests distinguish the sale-recording Cash Memo from a payment acknowledgement and the combined Tax Invoice / Receipt. All three repeated executions match their expected types. Both executed digit-boundary trials retain the genuine leading digit, exclude the adjacent rule and leave the covered prefix unclear. These are synthetic printed/raster controls, not human handwriting.

Payment and energy use the same source PDF containing an intentionally incorrect hidden OCR layer, but different custom.md and independently frozen answers. Both purposes match their configured workbook checks in all three repeats. This is evidence for the configured outputs, not independent proof that every page was visually inspected. No scored workbook cell differs among valid repeats of the same case. Raw output is captured for the coal cases but has no configured raw denominator.

Four openings (trials 2, 3, 4 and 12) initially stopped because the conservative command audit referred combined instruction reads for review. Maintainer inspection found only the installed SKILL.md and chat-start.md being read, with unchanged workspace snapshots. Hash-bound reviews then allowed the exact waiting sessions to continue. The initial incomplete records, automatic format failures and separate continuation outcomes remain preserved. No completed inaccurate result was replaced or retried.

The CLI trace exposes shell commands and model reading ledgers but does not independently establish image viewing in this batch. Rendering, a declared vision capability and the model's own checked status are not proof of visual attention. Consequently these scores do not qualify a general vision/handwriting claim or supersede the private 0.3.13 Fox findings.

## CLI implementation and local checks

Google/Gemini CLI and xAI/Grok Build 0.1.0 previews now have family prompts, adapter instructions, policy references and generated packages. Each was prepared locally on the same payment and energy scenarios without calling those models. Their evaluators deliberately return completed=false until live session/telemetry integration is implemented. No model is pinned, selected or recommended for those families yet.

Gemini delivery uses an explicit SKILL.md path outside automatic discovery directories. Grok's generated package uses its documented disable-model-invocation flag. The Codex skill validator passes the OpenAI and Gemini packages and xAI source. It rejects the generated Grok extension key because that validator is Codex-specific; the field is retained for Grok, and repository build/link/invocation checks pass. This is not a successful Grok native smoke test.

Current-PATH discovery finds Codex; Gemini and Grok are not found on PATH, which does not prove they are not installed. Authentication for those tools was not inspected. The current Python and PDF renderer pass local probes; Tesseract is unavailable through this probe and model vision is left unknown. No third-party CLI was installed, no account settings changed and no private files sent to another provider.

The 199 local tests cover processing/scoring, reproducible packages, public-only fixture enforcement, frozen-artifact drift, one-attempt reservation, scripted reply provenance, stale review rejection and read-only CLI discovery. They do not establish model accuracy.
