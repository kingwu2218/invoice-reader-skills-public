## Transport recovery and reproducibility

Each CLI execution initially encountered WebSocket reconnects and then used the CLI's HTTP fallback. The old adapter classified every top-level error event as terminal, so the first completed execution was initially marked invalid. Added a narrow classifier for recognized reconnection notices occurring before successful completion, with regression tests: notices alone, terminal failure, authentication errors and post-completion errors still fail.

The first saved stream was rechecked only after exit code zero, a successful completion event, the exact session ID, output availability, raw hash and package/dataset integrity all matched. Original classifications and a stream-hash review record remain in ignored storage. The output was not rerun, changed or cherry-picked. The next two executions used the corrected adapter directly. This changes evaluation telemetry, not the tested skill package or reference answers.
