# Raw line scoring regression

These independently specified synthetic strings test the evaluator, not model recognition. `invented-lines.pdf` is a fictional source label; no source PDF is provided and this is not a live model scenario. The reference is written explicitly, never generated by flattening the input or by processing its amounts.

The four invoice lines include two invoices on the same page, a readable inconsistent total (2 × 1,250.00 with a printed 2,490.00), a trailing dash and one wholly unreadable row. Two statement lines include dates as printed, a leading-zero reference and debit/credit placement. The baseline has **25 nonblank checks and 7 correct blanks**, with blanks excluded from accuracy. Four invoice rows and two statement rows are counted separately.

Run `python -m unittest discover -s tests -p test_raw_lines.py -v`. Controlled mutations verify missing/extra rows, row order, changing printed arithmetic, numeric/date reformatting, missing units, leading zeroes, invented values even when flagged unclear, and debit/credit swaps. The all-blank row is intentional: removing it must fail row coverage even when field accuracy remains 25 / 25. These are evaluator detection tests, never model pass rates.

For future model scenarios, copy the **reference format**, not these supplied answers: use `Raw line items` or `Raw statement lines` in a new frozen `expected.json`, supply actual source documents and custom settings to the model, and use the existing staged runner. Never add new graded columns to an old frozen model run and present it as a prospective result.

Line identity is source filename, document pages, document type, occurrence among documents sharing those attributes, and the one-based line position **within that document and collection**. Model-chosen document IDs and the values being graded are not matching keys. Same-page same-type documents and their rows must retain reading order; this deliberately does not optimally rearrange values to improve the score. `Pages` is the document page range, not evidence of the individual line's physical page. Row coverage alone does not prove the right values: reordering can preserve row counts while failing field checks.
